## UI Development Rules

- Use UIKit for all new UI implementation.
- Do not use SwiftUI for new screens, components, navigation, or layouts unless explicitly requested.
- Existing SwiftUI template code may be removed or replaced when implementing real application features.
- Build screens using UIViewController and UIKit views.
- Prefer Auto Layout with programmatic constraints using NSLayoutConstraint.
- Do not use Storyboards or XIBs unless explicitly requested.
- Use UINavigationController for push-based navigation where appropriate.
- Use UITabBarController for tab-based navigation where appropriate.
- Use UICollectionView or UITableView for list-based interfaces depending on the UI requirements.
- Keep UI rendering and user interaction inside UIViewController / UIView classes.
- Business logic must not be placed directly inside UIViewController.

## Project state

This is a fresh iOS app scaffold generated from Xcode's default "App" template (SwiftUI + Core Data). 

## Commands

There is no Swift Package Manager manifest or Makefile — this is a plain `.xcodeproj`, so all builds/tests go through `xcodebuild` (or Xcode itself). No custom scheme file has been committed yet; the default autogenerated scheme shares the project name.

Build (Debug, for iOS Simulator):
```sh
xcodebuild -project SecuritiesSimulation.xcodeproj -scheme SecuritiesSimulation -destination 'platform=iOS Simulator,name=iPhone 16' build
```

Run all tests (unit + UI):
```sh
xcodebuild -project SecuritiesSimulation.xcodeproj -scheme SecuritiesSimulation -destination 'platform=iOS Simulator,name=iPhone 16' test
```

Run a single test (Swift Testing syntax, used by the unit test target):
```sh
xcodebuild -project SecuritiesSimulation.xcodeproj -scheme SecuritiesSimulation -destination 'platform=iOS Simulator,name=iPhone 16' test -only-testing:SecuritiesSimulationTests/SecuritiesSimulationTests/example
```

List available simulator destinations if `iPhone 16` isn't installed:
```sh
xcrun simctl list devices available
```

Notes:
- `SecuritiesSimulationTests` uses the **Swift Testing** framework (`import Testing`, `@Test`, `#expect`), not XCTest — write new unit tests with `@Test` functions, not `XCTestCase` subclasses.
- `SecuritiesSimulationUITests` uses **XCTest**/`XCUIApplication` (the standard UI test template) — this is a separate target/framework from the unit tests.
- iOS deployment target is 26.5 (Swift 5.0 language mode per project settings, built with a recent Xcode/SDK).

## Architecture Guidelines

All new application features should use UIKit with MVVM.

Recommended responsibility split:

- View / UIViewController
  - UI rendering
  - Auto Layout
  - User interaction
  - Binding ViewModel state to UI
  - No business logic

- ViewModel
  - Screen state
  - Business logic
  - Input validation
  - Calls services/repositories
  - Exposes observable state to the ViewController

- Model
  - Domain models
  - API request/response models
  - Codable models

- Service
  - Networking
  - Persistence
  - External SDK integration

Prefer protocol-based dependency injection so ViewModels and Services can be unit tested.

Avoid placing networking, database access, or business rules directly inside UIViewController.
